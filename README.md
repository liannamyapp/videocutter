# Video Cutter

Frontend-демо сервиса нарезки видео: пользователь загружает видео, выбирает отрезок и получает готовый фрагмент. Вся обработка идёт в браузере, файл никуда не отправляется.

**Стек:** React 18, TypeScript, Vite, Vitest.

## Запуск

```bash
npm install
npm run dev      # режим разработки, http://localhost:5173
npm test         # юнит-тесты
npm run build    # production-сборка в dist/
```

## Возможности

- Загрузка видео кнопкой или drag-and-drop, проверка типа и размера файла
- Чтение метаданных: длительность, разрешение, размер
- Выбор отрезка ползунками, вводом таймкода (`1:05`, `01:05.5`, `65`) или кнопкой «← текущее»
- Визуальная шкала с выделенным отрезком и позицией воспроизведения
- Просмотр выбранного отрезка перед нарезкой
- Очередь задач со статусами: «В очереди» → «Обрабатывается» (с прогрессом) → «Готово» / «Ошибка»
- Просмотр, скачивание, повтор и удаление фрагментов
- Понятные сообщения об ошибках: неверный формат, некорректные таймкоды, неподдерживаемый браузер

## Архитектура

```
src/
├── App.tsx              — состояние приложения и очередь задач
├── types.ts             — типы видео и задач, тексты статусов
├── lib/
│   ├── time.ts          — форматирование/разбор таймкодов, валидация отрезка
│   ├── time.test.ts     — тесты для time.ts
│   └── trim.ts          — обрезка видео через captureStream + MediaRecorder
└── components/
    ├── Uploader.tsx     — загрузка файла
    ├── Trimmer.tsx      — плеер и выбор отрезка
    └── ClipList.tsx     — список фрагментов и их статусы
```

**Как работает обрезка.** Исходное видео воспроизводится в скрытом `<video>` с нужной позиции, его поток захватывается через `captureStream()` и записывается `MediaRecorder` в WebM до достижения конца отрезка. Это позволяет обойтись без сервера и без тяжёлых библиотек.

**Очередь.** Задачи обрабатываются строго по одной, в порядке добавления; флаг `busy` не даёт запустить две записи одновременно.

**Память.** Для каждого файла создаётся `blob:`-URL; при удалении фрагмента или смене видео он освобождается через `URL.revokeObjectURL`.

## Ограничения и что дальше

- Запись идёт в реальном времени: фрагмент в 30 секунд обрабатывается ~30 секунд. В продакшене обрезку стоит перенести на backend (Node.js + ffmpeg `-ss/-to -c copy` и очередь задач, например BullMQ), тогда она займёт доли секунды и сохранит исходный кодек.
- Результат сохраняется в WebM. Для MP4 нужен серверный ffmpeg или ffmpeg.wasm.
- Safari поддерживает `captureStream()` ограниченно; рекомендуются Chrome, Edge, Firefox.
- Следующие шаги: backend с авторизацией и хранением фрагментов в БД, деплой в Docker.
